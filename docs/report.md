## 摘要

本报告记录一项从文献调研到可运行工程的完整工作：在「金融 + 大模型」这一方向上检索 arXiv 近四年产出，抽取论文级可实践想法，选定**时间点正确（point-in-time）的泄漏审计评测**作为垂域，并实现为开源 Python 包 `finpit`。

**核心命题**：论文里「LLM 情绪因子 IC = 0.08」这类结论，有多少是信号本身，有多少是评测流程漏进来的？在真实市场上无法回答（不知道真实 IC），但在合成语料上可以——`true_ic` 已知，虚高因此能被精确归因。

**主要结果**（三条）：

1. **泄漏能凭空制造显著性，而诚实方法在弱信号上统计功效不足。** 同一实验台上，诚实的 IC 为 0.04 且 bootstrap 区间跨 0；泄漏版 IC 达 0.16–0.31，轻易「显著」。这解释了泄漏为何如此普遍，也印证了 `arXiv:2608.27734`「故意泄漏的 oracle 拿到 Sharpe=35 并完整通过 Deflated Sharpe 与 PBO 检验」的结论。

2. **不同泄漏污染不同指标，方向还相反。** 幸存者偏差把**均值收益**从 −0.00019 翻成 +0.00015 而 IC 几乎不动；未来函数与提示词泄漏则把 IC 抬高数倍而均值收益纹丝不动。**任何单一指标都不足以做泄漏诊断。**

3. **LLM 相对词典没有可测量的增益，但该对比对词典不公平。** 1,200 行 / 100 个决策日、按日分组 bootstrap 下，词典 IC +0.0456、LLM +0.0393，差 +0.0063，**p ≈ 0.541（不显著）**。由于新闻模板与词典词表同源，该结果不可外推为一般结论。

## 1. 背景：为什么选这个方向

### 1.1 文献给出的决定性证据

2025 下半年至 2026 年，金融 LLM 领域最集中的产出不是新模型，而是**「我们之前的数字不可信」的证据**。检索到的关键结论：

| 证据 | 出处 |
|---|---|
| 一个**故意泄漏**的 oracle 报 Sharpe=35，**完整通过** Deflated Sharpe 与 PBO 检验。统计修正只能惩罚「多次搜索」，无法识别「特征本身就是未来信息」。 | [`2608.27734`](https://arxiv.org/abs/2608.27734) |
| 随机切分相对时序切分把 MCC 抬高 **1.1×–6.5×**；FinBERT 端到端微调**放大**该差距。 | [`2608.17223`](https://arxiv.org/abs/2608.17223) |
| 标准零中心配对检验在**零技能**下假阳性率 **11.6%**；723 个财报事件上 gross **+15.2 bps/event** 分解为 composition **+25.8** 与 selection **−10.6**。 | [`2610.04040`](https://arxiv.org/abs/2610.04040) |
| 20 年、100+ 标的回测显示早期 LLM 择时优势来自幸存者偏差与数据窥探；该文 comment 明确记录 *"Corrected the FinAgent results"*。 | [`2505.07078`](https://arxiv.org/abs/2505.07078) |
| 模型的 effective cutoff 跨厂商相差 **22 个月**，比厂商自报**早最多 8 个月**。 | [`2607.18867`](https://arxiv.org/abs/2607.18867) |

**推论：防泄漏必须做进数据访问层，而不是事后做显著性校正。**

### 1.2 必须并列的反向证据

只引用支持自己方向的文献是学术不诚实。检索同时发现：

- [`2502.21206`](https://arxiv.org/abs/2502.21206)（Chronologically Consistent LLMs）测得 **"lookahead bias is modest"**；
- [`2607.11889`](https://arxiv.org/abs/2607.11889) 显示 PIT 模型与不受限模型的差距**可随规模缩小**。

因此正确的结论不是「全是假的」，而是：**泄漏幅度高度依赖模型与任务，而多数论文根本不披露时间对齐信息。** 问题在于**不可验证**，而不在于**必然造假**。

### 1.3 定位修正：空白已被部分占据

> **更正说明。** 本报告初稿曾声称「统一开源的泄漏审计工具链不存在」。该说法**不成立**。
> 事后检索发现已有多个同期项目，其中 FinTrace 的选题与本工作高度重合，且证据更硬
> （真实数据、更大基准）。此处如实更正，并据此重新界定本工作的定位。

| 项目 | 定位 | 与本工作的关系 |
|---|---|---|
| [FinTrace / PITfall](https://github.com/FredXing1/FinTrace) | 可审计的时间点金融研究 agent + PITfall 泄漏控制基准；**125M 条 as-filed 真实 EDGAR 事实**；实测 naive agent 用真值答出 82% 的「不可能问题」，gated agent 为 0% | **选题高度重合且更完整**。它有真实数据、200 任务基准、bootstrap CI。本工作在数据规模与基准设计上**不及它** |
| [nofuturedata](https://github.com/ORANGINGS/nofuturedata) | 时间泄漏 linter + fail-closed PIT guard；静态扫描 pandas 未来模式，用「未来输入扰动不变性」测试管线 | 占据了「**预防**」生态位。本工作的 `finpit.pit` 与之功能重叠，成熟度不及 |
| [timefence](https://github.com/gauthierpiarrette/timefence) | 训练管线中的静默数据泄漏防护 | 同上 |
| [backtest-bias](https://zenodo.org/records/22373468) | 价格面板的幸存者与完整性检查 | 本工作的 `cherry_pick` 消融与之相邻 |
| [pit-adjuster](https://pypi.org/project/pit-adjuster/0.1.0/) | PIT 数据调整 | 同上 |

**这改变了本工作的定位。** 上述项目都在回答「**如何防止**泄漏」，而**没有人在回答「每一类泄漏分别把你的哪个指标抬高了多少」**。
本工作的差异化在于**损害量化**：用已知 `true_ic` 的受控环境把虚高按泄漏类型归因，并指出不同泄漏污染**不同指标、方向还相反**。
这是与「防护类」工具**互补**而非竞争的定位。

必须诚实说明：这些项目多与本工作同期出现（FinTrace 创建于 2026-09-24），该方向尚未定型；
但「同期少有人做」不等于「有原创性」，本工作的贡献量级**明显低于** FinTrace。

## 3. 系统设计

### 3.1 时间点门控数据层（`finpit.pit`）

所有数据必须声明 `published_at`——**真正对公众可见的时刻**，而非事件发生时刻、也不是数据里的日期字段。读取必须经过 `as_of` 视图：

```python
with store.as_of(datetime(2024, 3, 1, 12, 0, tzinfo=UTC)) as view:
    view.get("AAPL:close")     # 放行
    view.get("AAPL:10-K")      # 该 10-K 到 3/5 才发布，于是：
# LookaheadError: 未来函数：在 as_of=2024-03-01 12:00 读取 'AAPL:10-K'，
#                 但该记录到 2024-03-05 14:00 才公开（早用了 98.0 小时）
```

关键设计：**「键不存在」与「键存在但尚未公开」是两种不同的结果**。混为一谈会让问题无法定位。

### 3.2 泄漏消融实验台（`finpit.eval`）

同一条信号送进多条评测流程，每条开启一个真实存在的研究陋习：

| 泄漏模式 | 对应的真实陋习 |
|---|---|
| `clean` | 严格时间点纪律（对照组） |
| `pit_violation` | **差一天**的未来函数：用目标日当天的新闻预测当天收益 |
| `outcome_prompt` | 提示词混入事后行情回顾（新闻 API 常返回被更新过的文章） |
| `test_set_select` | 在评测集上挑最优超参 |
| `cherry_pick` | 样本按结果筛选（幸存者偏差） |
| `oracle_latent` | 直读潜在真值——给出该信号族上限 |
| `future_return` | 把目标收益当特征——审计管线健全性自检 |

### 3.3 校准合成语料（`finpit.data`）

要**精确测量**虚高，必须知道真实信号强度——真实市场数据给不了。合成语料的价值不在「像真的」，而在 `true_ic` 已知。为避免沦为玩具，生成器复刻了真实市场的典型事实：

| 性质 | 实测值 | 真实市场量级 |
|---|---|---|
| 日收益标准差 | 0.0155 | 1%–3% |
| 超额峰度 | 15.99 | 5–30 |
| 波动率聚集（\|r\| 一阶自相关） | 0.19 | 正 |
| 目标 IC → 实测 IC | 0.035 → 0.0356 | 0.02–0.05 |

关键设定：**新闻的 `published_at` 晚于当日收盘**，其中约 40% 附带**当日行情播报**（「该股当日上涨 2.31%」）。后者是未来函数的高危区——这类新闻一旦被对齐到**同一天**的收益，就会凭空造出极高 IC，因为它复述的就是答案本身。

### 3.4 切分泄漏审计（`finpit.audit`）

对同一份特征、同一个模型，做随机切分 vs 时序切分的对照，报出虚高倍数。纯 numpy 实现（哈希字符二元组 + 逻辑回归），**刻意不引入 scikit-learn**——避免「用封装好的东西复现别人的结论」这种循环论证。

### 4.1 泄漏消融——词典基线

40 资产 × 750 交易日，12,000 行样本。**上帝视角真实 IC = 0.0356。**

|---|---:|---:|---:|---:|---:|---:|---:|
| `clean` | +0.0257 | +0.0329 | 0.5203 | +0.00069 | −0.00019 | — | 0 |
| `pit_violation` | +0.1216 | +0.1707 | 0.5915 | +0.00767 | −0.00019 | **+373.8%** | **12000** |
| `outcome_prompt` | +0.2091 | +0.2656 | 0.6478 | +0.01384 | −0.00019 | **+714.9%** | **12000** |

| `future_return` | +1.0000 | +1.0000 | 1.0000 | +0.03708 | −0.00019 | +3797.7% | 0 |

### 4.2 泄漏消融——LLM 打分

同一实验台换成 `deepseek-v4.1-flash`（240 行，匿名化开启）：

| 泄漏模式 | IC | RankIC | 命中率 | IC 虚高 | PIT 拦截 |
|---|---:|---:|---:|---:|---:|
| `clean` | +0.0468 | +0.0899 | 0.5749 | — | 0 |
| `pit_violation` | +0.1599 | +0.1714 | 0.5503 | **+241.5%** | 240 |
| `outcome_prompt` | +0.3148 | +0.3776 | 0.8190 | **+572.2%** | 240 |
| `test_set_select` | +0.0607 | +0.1241 | 0.5622 | +29.6% | 0 |
| `cherry_pick` | +0.0029 | +0.0444 | 0.5448 | −93.8% | 0 |

| `future_return` | +1.0000 | +1.0000 | 1.0000 | +2035.6% | 0 |

泄漏方向与词典一致，且**幅度更大**：`outcome_prompt` 的绝对 IC 达 **+0.3148**，是所有配置中最「好看」的数字，而它完全是假的。

> **注意**：本轮 `oracle_latent` 跑出 0.0891，远超真值 0.0356，说明 240 行（40 资产 × 仅 **6 个决策日**）样本过小。故下表是专门的补充实验。

### 4.3 LLM vs 词典：1,200 行 / 100 个决策日 + 按日分组 bootstrap

面板按决策日聚簇（同一时点的横截面不独立），故用**按日分组**的 bootstrap（2,000 次重抽样）估计标准误，而非朴素假设 n=1200 个独立样本。

| 方法 | IC | RankIC | bootstrap SE | 95% 区间 |
|---|---:|---:|---:|---|
| oracle（潜在真值） | +0.0695 | +0.0888 | 0.0267 | [+0.0163, +0.1207] |
| `lexicon-v1` | +0.0456 | +0.0534 | 0.0284 | [**−0.0087**, +0.0993] |
| `llm:deepseek-v4.1-flash` | +0.0393 | +0.0528 | 0.0278 | [**−0.0158**, +0.0919] |

词典 − LLM 的 IC 差 = **+0.0063**，95% 区间 [−0.0124, +0.0250]，双侧 **p ≈ 0.541** → **差异不显著**。

LLM 调用：100 次（其中 40 次命中缓存），解析失败 24/1200 = **2.0%**。

### 4.4 切分泄漏审计

```
受控模拟（标签具时间持续性，验证审计器灵敏度）：
  随机切分   MCC=+0.3673  准确率=0.6683
  时序切分   MCC=+0.3035  准确率=0.6576
  虚高倍数   MCC 1.21×   → 存在切分泄漏

真实任务（次日收益符号）：
  随机切分   MCC=−0.0027  准确率=0.4952
  时序切分   MCC=+0.0076  准确率=0.4950
  虚高倍数   MCC −0.36×   → 切分泄漏不明显
```

第二行是**刻意的诚实结果**：次日收益符号本身就是**不可学**的任务（IC 0.026 远不足以让符号分类超越抛硬币），没有可被放大的信号，自然无从泄漏。

参数扫描（未见于文献的补充观察）：

| noise | persistence | 随机 MCC | 时序 MCC | 虚高 |
|---:|---:|---:|---:|---:|
| 2.5 | 0.97 | +0.4418 | +0.3260 | **1.36×** |
| 2.5 | 0.99 | +0.5868 | +0.5249 | 1.12× |
| 4.0 | 0.97 | +0.4482 | +0.3564 | 1.26× |
| 6.0 | 0.97 | +0.4547 | +0.3588 | 1.27× |

**标签持续性越高，切分虚高反而越小**（0.97 → 1.36×，0.99 → 1.09×）：状态几乎不变时，两种切分表现趋同。这提示切分泄漏的严重程度与标签的时间结构直接相关。

## 5. 讨论

### 5.1 核心发现：统计功效不足 vs 泄漏制造显著性

**4.3 节最值得注意的不是 LLM 与词典谁高谁低，而是三个 95% 区间全部跨 0。**

面板真值 IC = 0.0695，而词典做出 0.0456、LLM 做出 0.0393——**在 100 个决策日的样本上都无法与零区分**。

而同一个实验台里，泄漏版 IC 是 0.16–0.31，轻松「显著」。

> **诚实方法在弱信号上统计功效不足，而泄漏能凭空制造显著性。**
> 一个研究者只要不小心泄漏，就能拿到可发表的结果；坚持不泄漏，往往什么都拿不到。

这把泄漏从「道德问题」还原为**激励结构问题**。这正是 [`2608.27734`](https://arxiv.org/abs/2608.27734) 那个「故意泄漏的 oracle 拿到 Sharpe=35 并完整通过所有统计检验」在日常实践中的样子，也是为什么**结构约束必须取代事后统计校正**。

### 5.2 不同泄漏污染不同指标

| 泄漏 | IC 影响 | 均值收益影响 |
|---|---|---|
| `cherry_pick`（幸存者偏差） | +3.5%（几乎不动） | **−0.00019 → +0.00015（翻转）** |
| `pit_violation` / `outcome_prompt` | **+373.8% / +714.9%** | 完全不动 |

**两类污染的维度不同、方向还相反。** 因此任何单一指标都不足以做泄漏诊断，框架必须同时报告相关性指标与水平指标——这是 `SignalMetrics` 同时保留 IC 与 `mean_return` 的原因。

### 5.3 IC 本身不是泄漏探测器

`pit_violation` 的 IC 更高（+373.8%），但**只看 IC 完全无法判断这是信号还是泄漏**。只有 PIT 审计层给出了 12,000 次越界的记录。这与 [`2608.27734`](https://arxiv.org/abs/2608.27734) 的结论一致：**统计量无法替代结构约束。**

### 5.4 文本抽取损失的量化

`oracle_latent`（+0.0391）逼近真实 IC（0.0356），词典基线只有 +0.0257——**词典法只榨出约 66% 的可得信号**。这个 gap 是评价任何抽取器（含 LLM）的**正确基准**，而不是跟随机猜比。

### 5.5 关于 LLM vs 词典的公平性

必须明确指出：**4.3 节的对比对词典有利，不是公平竞赛。**

新闻模板与词典词表同出于本工作作者之手——模板用「超预期」「砍单」，词典就收了这些词。词典实质上**知道答案词汇**；LLM 只拿到一句通用 prompt。

因此该结果**不能外推为「LLM 不如词典」的一般结论**。它只说明：**在词汇已被领域专家穷举的前提下，通用 LLM 至多打平。** 这与 [`2609.20198`](https://arxiv.org/abs/2609.20198)、[`2608.04200`](https://arxiv.org/abs/2608.04200)、[`2506.06335`](https://arxiv.org/abs/2506.06335) 的报告方向一致——LLM 在**经济层面**没有超过判别式基线。

## 6. 工程实录

### 6.1 凭据封禁事件（值得记录的失败）

首次接入 LLM 时，凭据在约 30 次调用后被服务端封禁。复盘发现三条客户端规范**全部违反**：

| 项 | 错误做法 | 正确做法 |
|---|---|---|
| session ID | **每请求随机 UUID** | 会话内稳定复用 |
| User-Agent | `python-httpx/0.28.1` | 自有标识 `finpit-research/0.1` |
| 请求节奏 | 2 分钟 26 次无间隔 | 节流 1.5s |

服务端条款明确写着监控滥用流量。**节流因此被实现为 `LLMClient` 的正式功能，而非可选优化**——它是正确性要求。

改用合规客户端 + 新 key 后，160 次调用全程稳定。

### 6.2 静默降级掩盖真实故障

用推理模型（`deepseek-v4-pro`）时，12 条新闻的思维链耗尽 `max_tokens`，`content` 返回空。而最初的代码会**静默回退到 `reasoning_content`**，把半截思维链当成答案——症状表现为**误导性的「JSON 解析失败」**，让人往解析器方向排查。

修复：
- `Completion` 记录 `finish_reason`；
- 被截断（`length`）时**拒绝**回退，并明确报出「被 max_tokens 截断」；
- 缓存回放同样恢复 `finish_reason`，否则同样误报。

效果：失败率从 13% 降至 2%。已有回归测试锁定该行为。

**教训**：静默降级会伪造出「模型很稳」的假象。失败必须被计数、被区分、被报告。

### 6.3 缓存带来的可复现性

LLM 结果按 `(model, messages, params)` 哈希落盘。171 条缓存（152 KB）使：

- 重跑对比实验**零 API 成本**；
- 4.3 节的 bootstrap 分析可反复调整而无需重新调用；
- 缓存键包含模型名（曾因缺失该字段，导致换模型时读到旧结果而做出错误对比）。

## 7. 局限（不粉饰）

1. **主力实验基于合成数据。** 合成数据是测量泄漏的**正确**工具（需要已知真值），但无法替代真实数据上的验证。真实数据接入是下一步。
2. **LLM 对比中词典占便宜。** 见 5.5 节，不可外推为一般结论。
3. **统计功效偏弱。** 100 个决策日下，真值 IC=0.07 的信号，两种方法的 95% 区间都跨 0。想可靠区分 0.04 与 0.05 量级的差异需要更多决策日，成本主要落在 LLM 调用上。
4. **LLM 路径存在约 2% 的截断失败率。** 失败样本退化为 `confidence=0` 占位符（在加权聚合中自动失效，不污染分数），但损失有效样本量。
5. **框架对弱泄漏灵敏度有限。** `test_set_select` 与 `cherry_pick` 的 IC 虚高仅 +3.8% / +3.5%（8 组候选超参高度相关）。
6. **`outcome_prompt` 是词典法也能捕捉的显式形态。** 更隐蔽的语义级结果泄漏需要 LLM 才能识别，尚未构造该形态的对照。
7. **未实现 LAP 泄漏探针**（[`2512.23847`](https://arxiv.org/abs/2512.23847)）与 **Availability Contract 校验器**（[`2610.21659`](https://arxiv.org/abs/2610.21659)）。
8. **未读论文全文。** 文献结论基于摘要与元数据；各论文的代码开源状态除 FinanceBench 外均标「未核实」。

---

## 8. 结论与展望

本工作验证了一个可操作的立场：**泄漏防御必须做进数据访问层。** 在 `true_ic` 已知的受控环境中，泄漏造成的虚高可以被精确量化（+373.8% 至 +714.9%），而不同泄漏污染的指标维度不同、方向还相反，因此必须联合诊断。

更重要的是，实验揭示了一个结构性问题：**诚实评测在弱信号上功效不足，泄漏却能制造显著性。** 这解释了泄漏为何普遍，也说明为什么仅靠「研究者自律」不够——需要把约束**做成基础设施**。

**下一步**（按价值排序）：

1. **真实数据接入**（SEC EDGAR + 行情，全流程 PIT）——把结论从合成推向真实；
2. **`LAP` 泄漏探针**（[`2512.23847`](https://arxiv.org/abs/2512.23847)）——诊断参数化后见之明；
3. **`AvailabilityContract` 校验器**（[`2610.21659`](https://arxiv.org/abs/2610.21659)）——强制事件内部时序约束；
4. **Trial Ledger 搜索强度记账** —— 累计试验数驱动 Deflated Sharpe / PBO；
5. **扩大决策日数量** —— 提升统计功效，使 0.04 与 0.05 量级可区分。
