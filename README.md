# finpit

**面向 LLM 金融信号的时间点正确（point-in-time）评测与泄漏消融框架。**

> 论文里"LLM 情绪因子 IC=0.08"这类结论，有多少是信号本身，有多少是评测流程漏进来的？
>
> 在真实市场上你无法回答，因为你不知道真实 IC。**在合成语料上可以** —— `true_ic` 是已知的，于是虚高能够被精确归因。

---

## 为什么做这个

2025 下半年到 2026 年，金融 LLM 领域最集中的产出不是新模型，而是**"我们之前的数字不可信"的证据**。几条最硬的：

| 证据 | 出处 |
|---|---|
| **一个故意泄漏的 oracle 报 Sharpe=35，完整通过了 Deflated Sharpe 与 PBO 检验。** 统计修正只能惩罚"多次搜索"，无法识别"特征本身就是未来信息"。 | [`arXiv:2608.27734`](https://arxiv.org/abs/2608.27734) |
| 随机切分相对时序切分把 MCC 抬高 **1.1×–6.5×**；FinBERT 端到端微调**放大**该差距（1.75×）。 | [`arXiv:2608.17223`](https://arxiv.org/abs/2608.17223) |
| 标准零中心配对检验在**零技能**下假阳性率 **11.6%**。723 个财报事件上 gross **+15.2 bps/event** 分解为 composition **+25.8** 与 selection **−10.6**。 | [`arXiv:2610.04040`](https://arxiv.org/abs/2610.04040) |
| 20 年、100+ 标的回测显示早期 LLM 择时优势来自幸存者偏差与数据窥探；该文 comment 明确记录 *"Corrected the FinAgent results"*。 | [`arXiv:2505.07078`](https://arxiv.org/abs/2505.07078) |
| 模型的 effective cutoff 跨厂商相差 **22 个月**，比厂商自报**早最多 8 个月** → 按日历设 placebo 无效。 | [`arXiv:2607.18867`](https://arxiv.org/abs/2607.18867) |

**结论：防泄漏必须做进数据访问层，而不是事后做显著性校正。**

必须并列的反向证据：也有工作测得 lookahead bias 幅度**温和**，且 PIT 模型与不受限模型的差距可随规模缩小（[`arXiv:2502.21206`](https://arxiv.org/abs/2502.21206)、[`arXiv:2607.11889`](https://arxiv.org/abs/2607.11889)）。所以正确的结论不是"全是假的"，而是：**泄漏幅度高度依赖模型与任务，而多数论文根本不披露时间对齐信息**。

## 这个仓库做了什么

三件事，都围绕"让泄漏当场炸出来，而不是靠事后怀疑"：

### 1. 时间点门控数据层（`finpit.pit`）

所有数据必须声明 `published_at`（**真正对公众可见的时刻**，不是事件发生时刻、也不是数据里的日期字段）。读取必须经过 `as_of` 视图，越界当场抛 `LookaheadError` 并量化早用了多少小时：

```python
store = PITStore("market")
store.add_many(records)

with store.as_of(datetime(2024, 3, 1, 12, 0, tzinfo=UTC)) as view:
    view.get("AAPL:close")     # 放行
    view.get("AAPL:10-K")      # 该 10-K 到 3/5 才发布，于是：
# LookaheadError: 未来函数：在 as_of=2024-03-01 12:00 读取 'AAPL:10-K'，
#                 但该记录到 2024-03-05 14:00 才公开（早用了 98.0 小时）[store=market]
```

关键设计：**"键不存在"与"键存在但尚未公开"是两种不同的结果**。混为一谈会让你无法定位问题。

### 2. 泄漏消融实验台（`finpit.eval`）

同一条信号送进多条评测流程，每条开启一个**真实存在的研究陋习**，量化各自的 IC 虚高：

| 泄漏模式 | 对应的真实陋习 |
|---|---|
| `clean` | 严格时间点纪律（对照组） |
| `pit_violation` | **差一天**的未来函数：用目标日当天的新闻预测当天收益 |
| `outcome_prompt` | 提示词混入事后行情回顾（新闻 API 常返回被更新过的文章） |
| `test_set_select` | 在评测集上挑最优超参 —— 几乎所有论文都犯 |
| `cherry_pick` | 样本按结果筛选（幸存者偏差） |
| `oracle_latent` | 直读潜在真值 —— 给出该信号族上限 |
| `future_return` | 把目标收益当特征 —— 审计管线健全性自检 |

### 3. 切分泄漏审计（`finpit.audit`）

对**同一份特征、同一个模型**做随机切分 vs 时序切分的对照，报出虚高倍数。纯 numpy 实现（哈希字符二元组 + 逻辑回归），不引入 scikit-learn —— 避免"用封装好的东西复现别人的结论"这种循环论证。

## 结果

### 泄漏消融（40 资产 × 750 交易日，词典基线，12000 行 / 300 个决策日）

95% 区间由**按决策日分组**的 bootstrap（2000 次重抽样）给出 —— 同一时点的横截面并不独立，对行朴素重抽样会低估标准误。

| 泄漏模式 | IC | 95% 区间 | RankIC | 命中率 | 均值收益 | IC 虚高 | PIT 拦截 |
|---|---:|---|---:|---:|---:|---:|---:|
| `clean` | +0.0257 | [+0.0069, +0.0440] | +0.0329 | 0.5203 | -0.00019 | — | 0 |
| `pit_violation` | +0.1216 | [+0.1051, +0.1389] | +0.1707 | 0.5915 | -0.00019 | **+373.8%** | **12000** |
| `outcome_prompt` | +0.2091 | [+0.1916, +0.2262] | +0.2656 | 0.6478 | -0.00019 | **+714.9%** | **12000** |
| `test_set_select` | +0.0266 | [+0.0085, +0.0455] | +0.0325 | 0.5203 | -0.00019 | +3.8% | 0 |
| `cherry_pick` | +0.0266 | [+0.0060, +0.0462] | +0.0325 | 0.5177 | **+0.00015** | +3.5% | 0 |
| `oracle_latent` | +0.0391 | [+0.0232, +0.0557] | +0.0466 | 0.5166 | -0.00019 | +52.5% | 0 |
| `future_return` | +1.0000 | [+1.0000, +1.0000] | +1.0000 | 1.0000 | -0.00019 | +3797.7% | 0 |

**上帝视角真实 IC = 0.0356。**

四条读得出的结论：

1. **不同泄漏污染不同指标，方向还不同。** `cherry_pick` 把均值收益从 **−0.00019 翻成 +0.00015**（幸存者偏差抬高收益水平），IC 却几乎不动；而 `pit_violation`、`outcome_prompt` 把 IC 抬高数倍，均值收益纹丝不动。**任何单一指标都无法同时发现这两类问题。**

2. **IC 本身不是泄漏探测器。** `pit_violation` 的 IC 更高（+373.8%），但只看 IC 你完全无法判断这是信号还是泄漏。只有 PIT 审计层给出了 12000 次越界记录。这与 [`arXiv:2608.27734`](https://arxiv.org/abs/2608.27734) 的结论一致：**统计量无法替代结构约束**。

3. **文本抽取本身有损失，且可量化。** `oracle_latent`（+0.0391）逼近真实 IC（0.0356），而词典基线只有 +0.0257 —— 也就是说词典法只榨出了文本中约 66% 的可得信号。这个 gap 是评价任何抽取器（含 LLM）的**正确基准**，而不是跟随机猜比。

4. **统计功效与样本量强相关，这一点必须说清楚。** 在本表（300 个决策日）中 `clean` 的区间 [+0.0069, +0.0440] **不跨 0**，信号可检出；但在下节 1200 行 / **100 个决策日**的配置里，同样强度的信号区间就跨 0 了。**「诚实方法拿不到显著结果」是样本量的函数，而非普适结论** —— 讨论泄漏的激励结构时必须如实标注这一点。

### LLM 抽取路径（真实调用实测）

同一套实验台换成 `deepseek-v4.1-flash` 打分（240 行，匿名化开启）：

| 泄漏模式 | IC | RankIC | 命中率 | IC 虚高 | PIT 拦截 |
|---|---:|---:|---:|---:|---:|
| `clean` | +0.0468 | +0.0899 | 0.5749 | — | 0 |
| `pit_violation` | +0.1599 | +0.1714 | 0.5503 | **+241.5%** | 240 |
| `outcome_prompt` | +0.3148 | +0.3776 | 0.8190 | **+572.2%** | 240 |
| `test_set_select` | +0.0607 | +0.1241 | 0.5622 | +29.6% | 0 |
| `cherry_pick` | +0.0029 | +0.0444 | 0.5448 | −93.8% | 0 |
| `oracle_latent` | +0.0891 | +0.1107 | 0.5400 | +90.2% | 0 |
| `future_return` | +1.0000 | +1.0000 | 1.0000 | +2035.6% | 0 |

泄漏方向的结论与词典基线一致，且**幅度更大**：`outcome_prompt` 的绝对 IC 达 +0.3148，是所有配置里最"好看"的数字，而它完全是假的。

**但这一轮的绝对 IC 不可信**：240 行 = 40 资产 × 仅 6 个决策日，`oracle_latent` 都跑出 0.0891（远超真值），说明样本太小。下面是专门的补充实验。

### LLM vs 词典：1200 行、100 个决策日、按日分组 bootstrap

| 方法 | IC | RankIC | bootstrap SE | 95% 区间 |
|---|---:|---:|---:|---|
| oracle（潜在真值） | +0.0695 | +0.0888 | 0.0267 | [+0.0163, +0.1207] |
| `lexicon-v1` | +0.0456 | +0.0534 | 0.0284 | [**−0.0087**, +0.0993] |
| `llm:deepseek-v4.1-flash` | +0.0393 | +0.0528 | 0.0278 | [**−0.0158**, +0.0919] |

词典 − LLM 的 IC 差 = **+0.0063**，95% 区间 [−0.0124, +0.0250]，双侧 **p ≈ 0.541** → **差异不显著**。

**三条必须说清楚的结论：**

1. **LLM 没有跑赢词典**，但差距在噪声内，因此正确的说法是"**无法区分**"，而不是"词典更好"。

2. **这个对比对词典有利，是不公平的。** 新闻模板和词典词表都是本仓库作者写的，词典实质上**知道答案词汇**（模板用「超预期」「砍单」，词典就收了这些词）。LLM 则只拿到一句通用 prompt。所以该结果**不能外推为「LLM 不如词典」的一般结论** —— 它只说明：在词汇已被领域专家穷举的前提下，通用 LLM 至多打平。

3. **最关键的发现：三种方法的 95% 区间全部跨 0。** 面板真值 IC = 0.0695，而词典做出 0.0456、LLM 做出 0.0393，**在 100 个决策日的样本上都无法与零区分**（对比上表 300 个决策日时 `clean` 区间不跨 0 —— 功效是样本量的函数）。

> 第 3 点解释了泄漏为何如此普遍：
> **诚实方法在弱信号上统计功效不足，而泄漏能凭空制造显著性。**
> 同一个实验台里，诚实的 IC 是 0.04，泄漏的 IC 是 0.16–0.31。
> 一个研究者只要不小心泄漏就能拿到可发表的结果；坚持不泄漏，往往什么都拿不到。
> 这正是 [`arXiv:2608.27734`](https://arxiv.org/abs/2608.27734) 报告的"故意泄漏的 oracle 拿到 Sharpe=35 并完整通过所有统计检验"在日常实践中的样子。
>
> **但必须限定这句断言的适用范围**：它成立的前提是**样本量不足 + 信号弱**。
> 本仓库的 300 决策日配置就已经能把真值 IC≈0.036 的信号检出来。
> 所以正确的表述是「**在常见的短样本、弱信号条件下**，诚实评测处于劣势」，而不是「诚实永远拿不到结果」。

**工程实录**：LLM 路径踩到一个值得记录的坑。用推理模型（`deepseek-v4-pro`）时，12 条新闻的思维链会耗尽 `max_tokens`，`content` 返回空 —— 而最初的代码会**静默回退到 `reasoning_content`**，把半截思维链当成答案，表现为"JSON 解析失败"这一误导性症状。修复方式：`Completion` 记录 `finish_reason`，被截断时拒绝回退并给出明确诊断；缓存回放也会恢复该字段，否则同样会误报。该行为已有回归测试锁定。

### 切分泄漏审计

```
受控模拟（标签具时间持续性）：
  随机切分   MCC=+0.3673  准确率=0.6683
  时序切分   MCC=+0.3035  准确率=0.6576
  虚高倍数   MCC 1.21×   → 存在切分泄漏

真实任务（次日收益符号）：
  随机切分   MCC=-0.0027  准确率=0.4952
  时序切分   MCC=+0.0076  准确率=0.4950
  虚高倍数   MCC -0.36×   → 切分泄漏不明显
```

**第二行是刻意的诚实结果**：次日收益符号本身就是**不可学**的任务（IC 0.026 远不足以让符号分类超越抛硬币），没有可被放大的信号，自然无从泄漏。这与 [`arXiv:2608.04200`](https://arxiv.org/abs/2608.04200)（QLoRA 提升分类 F1 至 0.862，但 28 个收益检验经 FDR 后**全部不显著**）和 [`arXiv:2609.11144`](https://arxiv.org/abs/2609.11144)（**人类一致度 ≠ 收益关联度**）同向。

## 关于合成数据

要**精确测量**泄漏造成的虚高，你必须知道真实信号强度 —— 真实市场数据给不了。所以本仓库用校准过的合成语料：`true_ic` 是已知的，"论文报的 IC"与"真实 IC"之差才可被干净归因。

为了让结论不沦为玩具，生成器刻意复刻了真实市场的典型事实：

| 性质 | 实测值 | 真实市场量级 |
|---|---|---|
| 日收益标准差 | 0.0155 | 1%–3% |
| 超额峰度 | 15.99 | 5–30 |
| 波动率聚集（\|r\| 一阶自相关） | 0.19 | 正 |
| 目标 IC → 实测 IC | 0.035 → 0.0356 | 0.02–0.05 |

关键设定：**新闻的 `published_at` 晚于当日收盘**，且其中约 40% 附带**当日行情播报**（"该股当日上涨 2.31%"）。后者是未来函数的高危区 —— 这类新闻一旦被对齐到**同一天**的收益，就会凭空造出极高的 IC，因为它复述的就是答案本身。

## 真实数据验证：SEC EDGAR

合成数据能精确测量泄漏，但替代不了真实验证。EDGAR 提供了现实世界最经典的未来函数来源 —— **三个不同的时间戳**：

| 字段 | 含义 |
|---|---|
| `reportDate` | 财报**归属**的会计期间结束日 |
| `filingDate` | 申报日期（只有日粒度） |
| `acceptanceDateTime` | EDGAR **实际接收**该申报的时刻（精确到秒，带时区） |

朴素做法按 `reportDate` 对齐基本面 —— 但那时财报根本还不存在。

**实测结果**（2,651 条 10-K/10-Q，47 家公司，1995–2026，全部来自 SEC 官方 API）：

| 表单 | 样本 | 期间结束 → 公众可得 | P10–P90 |
|---|---:|---|---|
| 10-K | 641 | **中位 69.8 天**（≈49 个工作日） | 51–93 天 |
| 10-Q | 2,010 | **中位 39.7 天**（≈29 个工作日） | 31–46 天 |

| 度量 | 结果 |
|---|---|
| 按 `reportDate` 对齐的管线，平均**有多少公司在用尚未公开的申报**做决策 | **29.9%** |
| 严格 PIT 门控在「期间结束日」读取该期申报的拦截率 | **2651 / 2651 = 100%** |

```bash
export FINPIT_SEC_CONTACT=you@example.com   # SEC 要求 User-Agent 带真实联系方式
python scripts/edgar_real_data.py --n 60
```

> **这个真实数据实验抓出了框架自身的一个缺陷，值得记录。**
> 初版用 `f"{cik}:{form}"` 作 PIT 键，把同一公司的历年申报**塌缩成一个键**：
> 在「本期期间刚结束」的时点去读，`PITView.get` 会**静默返回上一期的旧记录**而不抛异常，
> 实测拦截率只有 **3.5%**，门控形同虚设。改为精确到期间的键后升至 **100%**。
> **PIT 守卫的一类隐蔽失效：键的粒度决定了门控是否真的有效。**
> 该反例已固化为测试（`test_coarse_key_would_silently_pass`）。

## 第二层：测量误差（errors-in-variables）

`finpit.pit` 管的是**时间上不该看到的信息**。但还有一类偏误与时间无关：
**看得到，却测不准**。

### 问题

让 LLM 给文本打情绪分、把分数当自变量跑回归时，分数只是真实构念 ``θ`` 的含噪代理：

```
x = θ + u        ⟹        β̂ → β · λ,   λ = Var(θ) / (Var(θ) + σ²_u)
```

`λ` 称为**可靠性**。这不是随机误差，而是**系统性偏差**——样本再多也消不掉，
只会让 `β̂` 越来越稳定地收敛到 `β·λ` 这个错的值。

`arXiv:2609.31013` 报告跨模型秩相关仅 **0.52**，意味着 `λ` 只有 0.5 量级。

### 无需真值即可识别 λ

K 个**平行指标**（K 个不同 LLM）两两相关系数的均值就等于单指标可靠性 ——
这就是 Spearman-Brown / Cronbach's α 的经典内容，把它用在 LLM 变量上即可直接回答：
**你的 LLM 因子有多少是噪声？**

### 实测结果（受控环境，真实效应 β = 0.10）

**1. 单变量衰减与修正**

| λ（可靠性） | β̂ 观测 | β̂/λ 修正 | 原始误差 | 修正后误差 |
|---:|---:|---:|---:|---:|
| 0.30 | 0.03227 | 0.10757 | 67.7% | 7.6% |
| **0.52** | **0.05459** | **0.10499** | **45.4%** | **5.0%** |
| 0.80 | 0.08216 | 0.10270 | 17.8% | 2.7% |
| 0.95 | 0.09627 | 0.10134 | 3.7% | 1.3% |

> 在文献报告的 λ=0.52 下，一个真实效应为 0.10 的因子会被报成 **0.055 —— 恰好一半**，
> 于是看起来"没什么效果"。修正后恢复到 0.105。

**2. 多模型的价值与天花板**

| K | λ_K | 噪声占比 |
|---:|---:|---:|
| 1 | 0.520 | 48.0% |
| 3 | 0.765 | 23.5% |
| 5 | 0.844 | 15.6% |
| 10 | 0.916 | 8.5% |
| 50 | 0.982 | 1.8% |

达到 λ = 0.90 需要**约 9 个模型**；从 10 个加到 50 个只从 0.915 升到 0.982 —— **边际收益早已消失**。

**3. 多变量符号翻转**

回归 `y ~ β₁·LLM情绪 + β₂·传统因子`，两者真实相关 ρ，**只有 LLM 变量带测量误差**：

| 设定 | LLM 系数 | 传统系数 |
|---|---|---|
| ρ=+0.8, 误差方差=1.5 | 0.10 → +0.0194 | 0.05 → **+0.1145**（放大 2.29×） |
| ρ=−0.7, 误差方差=1.5 | 0.10 → +0.0254 | 0.05 → **−0.0022**（**符号翻转**） |

> **传统变量本身没有任何测量误差，其系数依然被污染。**
> 只要回归里混入 LLM 生成的变量，**所有**系数的解释都要打折扣 ——
> 而这一点在实证论文里几乎从不被讨论。这就是"系数符号随模型而变"的机制。

**4. 前提失效：共享偏差无法被平均消除** ⚠️

上面第 2 点的结论**依赖"各模型误差相互独立"**。而 LLM 共享训练语料与架构先验，
这个前提很可能不成立。设误差 `u_k = c + e_k`（`c` 为所有模型共有的系统性偏差）：

| K | λ̂（两两相关，会高估） | λ_K（Spearman-Brown） | λ 真实 | 高估幅度 |
|---:|---:|---:|---:|---:|
| 2 | 0.750 | 0.857 | 0.571 | 50.0% |
| 10 | 0.750 | 0.968 | 0.645 | 50.0% |
| 200 | 0.748 | 0.998 | 0.666 | 50.0% |

| 量 | 值 |
|---|---|
| 两两相关估出的 λ̂₁ | 0.750 |
| 真实 λ₁ | **0.500**（高估 **50%**） |
| Spearman-Brown 预测 K→∞ 时 λ | **1.000** |
| 真实可靠性天花板 | **0.667**（被共享偏差卡死在 `v_θ/(v_θ+v_c)`） |
| 用 λ̂ 修正后的 β | 0.0675 vs 真值 0.10 → **仍偏低 32.5%** |

> **多模型集成消不掉共享偏差，而标准可靠性估计器会让你以为能。**
> 本模块因此提供 `error_correlation()` 前提检验 —— **集成多个 LLM 之前必须先查误差相关性**，
> 否则会得到一个"看起来很像那么回事"的修正量，实际仍严重低估。

**5. 真实 LLM 实测：跨模型一致性 ≠ 构念效度** ⚠️

5 个**不同厂商**的模型（deepseek-v4.1-flash / glm-5.3-flash / kimi-k3 / mimo-v2.6-flash /
longcat-2.5-preview-free）给同一批 200 条新闻打分，潜在情绪 `θ` 已知：

| 模型 | 与真实构念 θ 的相关 |
|---|---:|
| deepseek-v4.1-flash | +0.732 |
| glm-5.3-flash | +0.694 |
| kimi-k3 | +0.714 |
| mimo-v2.6-flash | +0.725 |
| longcat-2.5-preview-free | +0.710 |

| 量 | 值 | 含义 |
|---|---:|---|
| **跨模型两两相关** | **+0.9716** | 五个模型高度一致，看起来非常可靠 |
| **与真实构念的相关** | **+0.7150** | 但它们跟"要测的东西"只有中等相关 |
| **一致性 − 效度落差** | **+0.2566** | 这个落差就是陷阱 |
| 由一致性估出的 λ̂₁ | 0.9716 | → 会得出「**几乎无测量误差，不需要修正**」 |
| **真实 λ₁** | **0.5352** | → 实际有 **46% 的方差是噪声** |
| 误差平均相关 | **+0.9788** | 平行指标假设**彻底失效** |
| **集成 5 个模型的效度增益** | **−0.0079** | **负的** |

> **这是本次最有价值的发现：跨模型一致性不是效度证据。**
> 五个来自不同厂商的模型彼此相关 0.97，却各自只与其应测量的构念相关 0.72。
> 若你按"集成多个 LLM 更稳健"的惯例取平均，可靠性估计会告诉你 λ≈0.994（几乎完美），
> 而真实衰减因子是 0.524 —— **一半的信号被当成噪声丢掉了，且你毫无察觉**。
>
> 更反直觉的是：**集成不但没有提升效度，还略微变差**（0.7316 → 0.7237）。
> 因为各模型共享的那个巨大共同成分**并不是真实构念**，平均它不会提升效度，
> 只会把有信息量的个体差异一并抹平。

> **Caveat（必须说清）**：本实验的文本来自合成语料的**模板化标题**（5 正 5 负句式）。
> 模板措辞固定，很可能**放大**了跨模型共同成分 —— 各模型都在对同一批关键词做同一套映射。
> 在真实、多样化的语料上这个落差应当更小。因此上述数字应读作
> **"该机制确实存在且量级可观"的证据，而非"LLM 情绪分数的可靠性就是 0.53"的普适估计**。
> 把这个实验搬到真实文本上是下一步最该做的事。

```bash
python scripts/eiv_measurement_error.py            # 受控实验，不需要 API key
python scripts/eiv_real_llm.py --n 200             # 5 个真实 LLM 的跨模型可靠性
```

## 已知局限（不粉饰）

1. **这不是原创性工作，选题已被更完整的项目占据。** [FinTrace](https://github.com/FredXing1/FinTrace) 用 125M 条真实 EDGAR 事实做 PIT 研究 agent 与泄漏控制基准，证据比本仓库硬得多。本仓库的差异化只在「损害量化」这一窄缝。**不应被当作有原创贡献的研究成果引用。**
2. **主力实验基于合成数据。** 合成数据是测量泄漏的**正确**工具（需要已知真值），但它无法替代真实数据上的验证。真实数据只做到了 EDGAR 披露延迟这一个点，**尚未接行情、尚未在真实收益上跑完整消融**。
3. **合成语料是玩具级的。** 5 条正面模板 + 5 条负面模板，任何审稿人都会立刻指出这一点。
4. **`test_set_select` 与 `cherry_pick` 的虚高幅度偏小（+3.8% / +3.5%）。** 8 组候选超参高度相关，最大值相对真值的乐观偏差有限。这是诚实结果，不是 bug —— 但意味着本框架对**弱泄漏**的灵敏度有限。
5. **LLM 对比中词典占便宜，不是公平竞赛。** 新闻模板与词典词表同出一人之手，词典实质上知道答案词汇。该对比只能说明「词汇已被穷举时通用 LLM 至多打平」，不能外推。
6. **LLM 路径存在约 2% 的截断失败率。** 推理/长思维链模型会偶发耗尽 `max_tokens`，这些样本退化为 `confidence=0` 占位符（在加权聚合中自动失效，不污染分数），但会损失有效样本量。
7. **`outcome_prompt` 泄漏是词典法也能捕捉的显式形态。** 更隐蔽的语义级结果泄漏（如「次日机构评级上调」这类前瞻性表述）需要 LLM 才能识别，尚未构造该形态的对照。
8. **IC 估计的统计功效依赖样本量。** 100 个决策日下真值 IC=0.07 的信号区间跨 0；300 个决策日下真值 IC≈0.036 就能检出。想可靠区分 0.04 与 0.05 量级需要更多决策日，成本主要落在 LLM 调用上。
9. **未实现 LAP 泄漏探针**（[`arXiv:2512.23847`](https://arxiv.org/abs/2512.23847)）与 **Availability Contract 校验器**（[`arXiv:2610.21659`](https://arxiv.org/abs/2610.21659)）。已在路线图中。

## 相关工作 —— 以及一处必须更正的声明

> **更正。** 本仓库初稿声称「统一开源的泄漏审计工具链不存在」。**该说法是错的。**
> 事后检索发现已有多个项目在做这件事，其中 FinTrace 的选题与本仓库高度重合、且证据更硬。

| 项目 | 定位 | 关系 |
|---|---|---|
| [FinTrace / PITfall](https://github.com/FredXing1/FinTrace) | 可审计的时间点金融研究 agent + 泄漏控制基准；**125M 条 as-filed 真实 EDGAR 事实**；naive agent 用真值答出 82% 的「不可能问题」，gated agent 为 0% | **更完整**：有真实数据、200 任务基准、bootstrap CI。本仓库在数据规模与基准设计上不及它 |
| [nofuturedata](https://github.com/ORANGINGS/nofuturedata) | 时间泄漏 linter + fail-closed PIT guard；静态扫描 pandas 未来模式；用「未来输入扰动不变性」测试管线 | 占据了「**预防**」生态位，本仓库的 `finpit.pit` 与之重叠 |
| [timefence](https://github.com/gauthierpiarrette/timefence) | 训练管线的静默数据泄漏防护 | 同上 |
| [backtest-bias](https://zenodo.org/records/22373468) | 价格面板的幸存者与完整性检查 | 与 `cherry_pick` 消融相邻 |
| [pit-adjuster](https://pypi.org/project/pit-adjuster/0.1.0/) | PIT 数据调整 | 同上 |

**这改变了本项目的定位。** 上述项目都在回答「**如何防止**泄漏」，而**没有人在回答「每一类泄漏分别把你的哪个指标抬高了多少」**。
finpit 的差异化在于**损害量化**：在已知 `true_ic` 的受控环境中把虚高按泄漏类型归因，并指出不同泄漏污染**不同指标、方向还相反**。
这是与「防护类」工具**互补**而非竞争的定位。

诚实说明：这些项目多与本仓库同期出现（FinTrace 创建于 2026-09-24），该方向尚未定型；
但「同期少有人做」不等于「有原创性」——**本仓库的贡献量级明显低于 FinTrace**。
